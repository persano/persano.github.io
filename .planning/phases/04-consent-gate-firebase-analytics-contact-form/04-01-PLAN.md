# Plan 04-01: Consent Gate + Firebase Analytics (FIRE-01..03)

**User story:** As a visitor (and as the site owner's GDPR obligation), I want an explicit consent choice before any measurement SDK bytes touch my browser, so that analytics runs only when I said yes — and denying is exactly as easy as granting.

- **Files:** `js/consent.js`, `js/firebase-config.js`, `js/contact.js`, `firebase/firestore.rules`, `geohist/contact.html`
- **Globals:** `window.persanoFirebaseConfig` (classic-script config object, public-by-design)

Create js/consent.js: a classic defer IIFE mirroring the i18n.js house style ('use strict', zero globals, localStorage guarded in try/catch). It owns:
1. A consent store reading/writing the single D-42 family localStorage key holding JSON `{v:1, analytics:'granted'|'denied', ts:<ISO-8601>}`. Read must validate shape (v===1, analytics in the two values, ts is a string) and return null for absent/malformed; a storage write failure leaves the choice session-only (fail-closed — banner returns next visit).
2. Banner control: at init, if no valid stored choice, remove the `hidden` attribute from the page's static `.consent-banner` section; bind ONE click handler on the section that routes Accept/Reject button clicks; each click persists the choice with a fresh ISO timestamp and hides the banner.
3. On a granted choice (initial read or Accept click): the post-grant loader — dynamic import of the pinned 12.18.0 CDN modules: the app module first (to call its initializeApp with window.persanoFirebaseConfig), then the Analytics SDK module; wrap initialization in `isSupported()` and only call getAnalytics when supported (Pitfall 3); on load, if the stored choice has flipped to denied meanwhile, immediately call the retraction lever (setAnalyticsCollectionEnabled(analytics, false)) and skip event wiring (Pitfall 10 race guard); any import/init failure degrades silently — the page must never break (research Pattern 2 .catch policy).
4. Event wrappers, wired ONLY after a successful analytics instance exists: a click listener on each .badge-cta anchor sending `play_badge_click {page: location.pathname}` (D-51); a document-level listener for the persano:langchange CustomEvent sending `language_switch {from: detail.from, to: detail.to}` — log EVERY occurrence including the init-time auto-apply (locked choice from research Open Question 1; zero engine changes). Wrappers check the current stored choice at call time and no-op unless it is granted, so retraction stops sends with zero unload logic (D-44).
5. Retraction UI: bind a click handler on the footer anchor carrying class `consent-reopen` that re-opens the banner (remove hidden) regardless of stored choice; an Accept there re-grants (calling setAnalyticsCollectionEnabled(analytics, true) if the instance already exists this session), a Reject there flips the stored choice and, if the SDK is loaded, disables collection and stops future wrapper sends.

Banner markup (static, duplicated later in Task 2): insert into geohist/index.html just before the closing body tag — a `<section class="consent-banner" role="region" aria-label="Cookie consent" data-i18n-attr="aria-label:consent.banner.aria" data-i18n-attr-only hidden>` block containing one `<p data-i18n="consent.banner.text">` with short EN copy explaining analytics consent, and exactly two `<button type="button">` elements keyed `consent.banner.accept` ("Accept") and `consent.banner.reject` ("Reject") — equal prominence, no other controls. Ship the section with `hidden` so returning visitors never see a flash; consent.js un-hides it when no valid choice exists.
