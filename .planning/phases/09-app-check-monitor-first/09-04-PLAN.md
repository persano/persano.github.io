Keep everything else — honeypot swallow, validation, double-submit guard, lazy import, init order, ReCaptchaEnterpriseProvider init (cache-once guard), dormant gate — untouched.

1. Add a `TOKEN_TIMEOUT_MS = 10000` constant beside the other module constants. Rationale: the only observable failure seam is the explicit getToken call (SDK swallows failures elsewhere); unbounded await = dead form.
2. Add a local helper (inside the IIFE, zero new globals) that races a settled getToken promise against a timer: on settle, clear the timer and pass through; on timeout, reject with a synthetic Error carrying code `appCheck/token-timeout` (the case-tolerant family regex in the catch mapping matches it). A late-settling getToken after the race is harmless — the returned token object is never read (the SDK auto-attaches via the X-Firebase-AppCheck header).
3. In the active-site-key branch, wrap the getToken call with that helper and attach a `.catch` that RECORDS the failure code into a local variable (use the caught error's `code` when present; fall back to the synthetic timeout code) and then SWALLOWS the rejection — return normally so the chain proceeds. In the dormant branch (empty site key) nothing changes: no appcheck init, no race, no recorded failure, byte-identical behavior to pre-G-09-5.
4. Keep the existing `.then` (signInAnonymously + addDoc, optional-name guard, serverTimestamp, token never in payload) exactly as is. After the addDoc resolution, add a step: when the recorded failure code is non-empty, throw a synthetic Error carrying that code so the EXISTING onSubmit `.catch` maps it. Do not duplicate mapping logic inside send() — the onSubmit catch remains the single mapping point.
5. Do not change onSubmit's catch behavior: appcheck-family codes and permission-denied still route to the keyed appcheck status + the persano:appcheck dispatch (detail.code truncated to 40 chars — the synthetic timeout code is 22 chars); everything else still routes to the generic error; the `.finally` still re-enables the button on every path; the appcheck path must NOT reset the form (fields stay so the visitor can copy them into the email fallback; manual resend only — no auto-retry, per D-07).
