<objective>
Close gap G-06-9 (UAT test 9: "changelog is only in english, even when setting site to spanish") per the owner's decision: **Notice only** — no translate button, no Google Translate widget, no third-party script. Browser-native translation (Chrome/Edge/Safari) remains the mechanism for the EN-only entry content.

The fix has two parts:
1. A keyed, translated one-line notice on the changelog page ("Entries below are shown in English") so es/pt-BR visitors understand WHY part of the page reads in English.
2. The same communication on the privacy policy page, via the least invasive path that respects the documented design decision that privacy.html is deliberately keyless and scriptless (06-01 D-13; research Pitfall 5).

**Privacy approach diagnosis (documented decision):** Keying privacy.html was considered and rejected. A swap key on that page would be dead weight — the page loads no scripts, so the i18n engine could never apply the translation (the exact dead-key trap 06-01 explicitly avoided). Keying it would also force loading i18n.js on a page that is deliberately script-free and add a keycheck registration, all to display one sentence. Chosen path: keep privacy.html plain (zero keys, zero scripts, unregistered in keycheck) and ship a static trilingual one-liner (EN — ES — PT) that every visitor can read in their own language. Least invasive, zero gate surface change, communicates fully.

Output: notice live on both pages, keycheck PASS at 170, full validate battery green, deploy push gate (deferred pending this UAT resolution) unblocked.
</objective>
